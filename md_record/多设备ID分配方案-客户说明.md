# 多设备 ID 自动识别与分配方案（客户说明）

> 适用场景：一条 RS485 总线上挂接多台从机设备（支持 10~30 台），主机需要对每台设备进行 ID 分配与管理。
> 前提：所有从机出厂默认 ID 均为 1，直接使用会产生 ID 冲突。

## 1. 方案概述

本方案解决"多台同型号设备出厂 ID 相同，无法在总线上区分"的问题。核心思路是：

- 每台设备内置**全球唯一的芯片 UID**（96 位，出厂固化，无法修改），作为设备的"身份证"；
- 主机广播一条指令，总线上所有设备自动、依次上报自己的 UID 和当前 ID，**全程无需人工干预，也无需逐台接线**；
- 您根据收到的清单，决定每台设备分配什么 ID（也可以由您的上位机软件自动编排）；
- 主机逐台下发"UID + 新 ID"的绑定指令，设备各自核对 UID 后写入，完成分配；
- 最后主机可逐台回读验证，确保分配正确。

**整个过程只需要在总线上操作，不需要拆机、不需要按键、不需要临时单接。**

## 2. 分配流程（您视角）

### 第 1 步：设备清点

您（或您的上位机）在总线上广播一条"收集指令"，然后等待几秒钟（默认波特率 9600 下约 3~4 秒/轮，一般 2~3 轮即可收集完毕）。

总线上每台设备都会自动上报一帧数据，内容为：**本机 UID（12 字节）+ 当前 ID**。

收集完成后您得到一张完整清单，例如：

| 序号 | UID | 当前 ID | 说明 |
|---|---|---|---|
| 1 | 1A2B3C4D5E6F7890AABBCCDD | 1 | 未分配（出厂态） |
| 2 | 11223344556677889900AABB | 1 | 未分配 |
| 3 | DDEEFF001122334455667788 | 5 | 已分配过，当前 ID=5 |

这张清单还能帮您做日常管理：

- 查看哪些 ID 已经被占用，避免重复分配；
- 发现 ID 冲突的设备（清单里会出现两台 ID 相同的设备）；
- 随时重跑一遍即可盘点在线设备。

### 第 2 步：分配 ID

您决定每台 UID 对应的新 ID，然后**逐台**下发绑定指令：指令中携带目标设备的 UID 和您指定的新 ID。

- 总线上所有设备都会收到该指令，但**只有 UID 与指令一致的设备才会执行**，其余设备不受影响；
- 因此即使总线上所有设备都是 ID=1，也能准确地把新 ID 发到指定的那一台；
- 首次分配和以后修改 ID 使用**同一条指令**。

### 第 3 步：验证

对每台已分配的设备，用新 ID 读取其 UID 寄存器并与清单比对。全部一致即分配完成。

## 3. 您需要实现的部分（主机侧）

如果您使用自研主机/上位机软件，需要实现以下三个 Modbus 报文的发送与解析（均为标准 Modbus RTU 帧 + CRC16）：

| 报文 | 方向 | 作用 |
|---|---|---|
| 收集指令（广播） | 主机 → 总线 | 触发所有设备分时上报 UID + 当前 ID |
| UID 上报帧 | 设备 → 主机 | 设备的自动响应，主机接收并解析（含 CRC 校验，错误帧直接丢弃） |
| 绑定指令（广播） | 主机 → 总线 | 携带目标 UID + 新 ID，指定设备执行写入 |

具体的报文格式（寄存器地址、字节布局、时序参数）见我方提供的**通信协议文档**。

主机侧的实现建议：

1. **收集阶段**：广播后静默接收若干轮，记录收到的所有"UID + 当前 ID"；连续 1~2 轮没有收到新 UID 即认为收集完成（总时长一般不超过 20 秒）；
2. **分配阶段**：逐台下发绑定指令，等待设备应答（建议超时 ≥300ms，设备写入需要时间）；一台上一步确认成功后再发下一台；
3. **验证阶段**：用新 ID 读 UID 寄存器比对。

## 5. 常见问题

**Q：新设备中途加入总线怎么办？**
A：重新跑一遍收集流程即可，新设备会上报 UID，再走分配流程。

**Q：一台设备的 ID 想改，会影响其他设备吗？**
A：不会。绑定指令按 UID 精确匹配，只有目标设备执行。

**Q：两台设备 ID 已经配成了相同的怎么办？**
A：不影响。收集上报不依赖 ID（按 UID 分时上报），两台的 UID 都能正常收到，逐台重新分配即可理顺。

**Q：分配后的 ID 会掉电丢失吗？**
A：不会。ID 写入非易失存储器，掉电保持。

**Q：广播会干扰总线上正在进行的正常通信吗？**
A：分配流程建议在设备空闲时执行（如产线配置阶段）。流程结束后总线恢复正常主从轮询。
