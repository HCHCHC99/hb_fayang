# 控制超时故障检测方案

> 状态：**方案（待实现）**
> 更新时间：2026-09-29
> 关联：`捷昌-南京和本Modbus RTU 协议说明v.2.0.md`、`电机仲裁系统设计说明.md`、`关窗基准点.md`、`点动.md`

---

## 一、需求背景

原控制逻辑：上位机下发控制指令后，执行器立即应答"已收到"并开始执行，但**执行结果无从得知**。

典型工况：执行器内部电机与外接旋转机构之间的**齿轮箱损坏** —— 电机仍在转，外部机构却不动。此时上位机无法判断执行器是否故障。

客户要求：下发指令后，在规定时间内若未完成相应动作，则报"控制超时故障"（体现在故障位）。

---

## 二、故障边界（重要，需对客户说明）

**本检测只能覆盖"电机侧"故障，覆盖不了齿轮箱打滑。**

原因：角度反馈来源于**电机霍尔**（`RunAngle_Update()` 用 `g_s32HallPulseAccum`；`dev_rturn` 的 `fCurrentAngle` 由电机霍尔转速积分）。齿轮断开时电机空载仍转 → 霍尔照常计数 → 角度估算照常推进。

| 故障 | 类型1 开/关窗 | 类型2/3 到角度 |
|---|---|---|
| 电机堵转/不转但过流未到阈值 | ✅ 可检测 | ✅ 可检测 |
| 电机指令有效但停不下来（关窗一直转） | ✅ 可检测 | — |
| 驱动失效、电机无输出 | ✅ 可检测 | ✅ 可检测 |
| **齿轮箱打滑（电机转、输出不转）** | ✅ 可检测（电机空转永不堵转） | ❌ **检测不到**（角度照常到位） |

---

## 三、方案总览

分两类指令，各用一套独立检测：

| 类别 | 指令 | 入口 | 完成判据 |
|---|---|---|---|
| **类型1** | 直接开窗 / 关窗 | `CTRL_CMD`(0x2720) bit4 / bit5 | 关窗=堵转过流；开窗=开窗极限角 |
| **类型2** | 转到目标角度 | 0x2727/0x2728 连写触发 | 角度进入容差 |
| **类型3** | 回到关窗基准点 | `REG_ABS_CMD`(0x2725)=1 | 角度进入容差 |

> 点动 Jog（0x272B/0x272C）底层同为 `RunAngle_GotoTarget()`，**纳入类型2/3**。

判定核心：**"某次运动进行中"到截止时刻仍未完成 → 报超时**。

## 四、参数与故障位

### 4.1 新增参数（存 Flash）

| 参数 | 地址 | 类型 | 语义 | 默认 | 备注 |
|---|---|---|---|---|---|
| `T1_TIMEOUT_S` | 0x2717 | uint16 / 秒 | 类型1 固定超时时间；**0=关闭类型1检测** | 0 | 需 ≥ 全行程+堵转时间 |
| `M_MARGIN_S` | 0x2718 | uint16 / 秒 | 类型2/3 估算余量 | 2 | |

> 地址避开已被占用的：0x2713（ID 分配协议）、0x2710（ID 绑定/查询）、0x272B/0x272C（点动）、0x2715（欠压阈值）。

### 4.2 复用参数

| 参数 | 地址 | 用途 |
|---|---|---|
| `REG_TARGET_SPEED` | 0x2711 | 类型2/3 估算用标称转速，**定义为输出轴 r/min**；**0=关闭类型2/3检测** |
| `REG_ABS_THRESHOLD` | 0x2726 | 到位容差 `goto_zero_thresh_x10`（0.1°，默认 `ABS_THRESH_DEFAULT_X10=6`=0.6°，范围 0~200） |

> 注意：`0x2725` 是命令寄存器（设/回基准点），**不是**容差阈值；容差用 **0x2726**。
> 超时判定必须复用 0x2726 的运行时值，与 `RunAngle` 的到位判据一致，避免出现"RunAngle 认为到位、超时逻辑认为没到位"的矛盾。

### 4.3 新增故障位

```c
#define FAULT_BIT_MOTION_TIMEOUT  (0x0080U)   /* bit7: 控制超时 */
```

现状占用：bit0 过压、bit1 开窗过流、bit2 关窗过流、bit3 复位、bit4 过载、bit5 堵转、bit6 欠压。

## 五、判定逻辑

### 5.1 统一计时起点

**指令被受理（门禁通过、发布运动事件）即起算**：`deadline = now + 设定时间`。不采用"首次观测到在转才计时"。

- 受理 → 事件 → 仲裁 仅几毫秒，相对秒级阈值可忽略；配合类型2/3 的余量 `M` 更无影响，故无需 `WAIT_START` 态。
- 起点是"**受理**"而非"Modbus 帧到达"：上锁 / 电机未停时收到的指令被门禁拒绝，**不启动检测**，避免上锁状态下误报。

判定"到点是否仍在转" = `!Param_IsMotorStopped()`
（= 霍尔方向 ≠ 0 **或** 仲裁期望方向 ≠ 0，见 `CtrlCmd_IsMotorRev()`）。
即"电机指令仍然有效"也算在转，从而覆盖"电机堵转/驱动失效但指令仍在"的故障。

被限位挡下（RTurn 给 `block_fwd/rev` 插 BLOCK）→ 仲裁期望方向变 0 → 判为"已停止" → **不报超时**。

### 5.2 类型1（开/关窗）

```
受理 → deadline = now + T1_TIMEOUT_S × 1000
到点：仍在转 (!Param_IsMotorStopped()) → 超时
```

### 5.3 类型2/3（到角度 / 回基准点）

```
角速度 ω(deg/s) = 0x2711 × 6            // 输出轴 r/min → deg/s
t_ms = dist_x10 × 1000 / (60 × 0x2711)  // dist_x10 = |目标角 - 实时角|（0.1°）
deadline = now + t_ms + M_MARGIN_S × 1000
到点：角度未进 0x2726 容差  且  仍在转 → 超时
```

- 实时角：`s_abs_offset_x10`（`RunAngle`）。
- 目标角：类型2=0x2727/0x2728；类型3=`close_limit_angle`(0x271C)。
- 到点做**一次**判定，判完即结束该次检测。

### 5.4 状态机

```
IDLE ──Start() 受理指令──▶ RUNNING ──停转/急停/上锁/故障/新指令──▶ IDLE
                             └ 到 deadline 仍未完成 ─▶ Trip
```

## 六、触发与锁定

超时触发时：

1. `RealTime_SetFault(FAULT_BIT_MOTION_TIMEOUT)` 置 bit7；
2. **急停** + **双向锁定**：往 `block_fwd` 与 `block_rev` 各插一条 BLOCK
   （新增 `DEV_ID_TIMEOUT_FWD/REV`，注册进 `c_device_genes[]`，`PRIO_LIMIT` + `CAP_BLOCK`）；
3. **必须同时 `Motor_ClearAllowFwd/Rev()`**（照抄 `Motor_OnRTurnLimit`）：
   否则清除故障移除 BLOCK 后，旧的"允许运行"指令仍在队列 → 电机会立即恢复转动 → 二次超时。

**清除**：`REG_FAULT_STATUS`(0x2740) 清除故障 → 清 bit7 + 移除双向 BLOCK → 解除锁定。

---

## 七、取消条件

出现以下任一，取消当前超时检测：

- 其他故障：过压 / 欠压 / 过流 / 堵转 / 过载
- 上锁、急停
- 清除故障
- 新的控制指令（**同类新指令 = 取消旧的 + 按新参数重新起算**）
- 电机停转（到位、堵转、极限）

---

## 八、误报抑制与边界

| 场景 | 处理 |
|---|---|
| 指令被门禁拒绝（未解锁 / 电机未停） | 不启动检测 |
| 已在极限又发开窗/关窗（ arbitration 被限位 BLOCK） | 不启动 → 不报 |
| 目标角已在容差内（`GotoTarget` 直接 return 不转） | 未发生运动 → 不报 |
| 校准 / 找基准（上电关窗找零、0x2725=1） | **不启用类型1检测**（本身是长堵转） |
| `T1_TIMEOUT_S = 0` | 类型1 检测关闭 |
| `0x2711 = 0` | 类型2/3 检测关闭（避免除零） |
| 类型1 正常全行程较慢 | `T1` 必须 ≥ 全行程 + 堵转时间，需现场调试 |

## 十一、验证方法

1. **类型1**：设 `T1` 为较小值，下发开窗后人为让电机空转/卡住不停止 → 到点应报 bit7 并锁定；清故障后应可恢复。
2. **类型2/3**：设 `0x2711` 为标称转速、`M` 适中，下发到目标角后人为拖慢/停住电机 → 到点角度未达且仍在转 → 应报 bit7。
3. **不误报**：正常开/关窗到极限、正常到目标角到位、被限位挡下、目标已在容差内 → 均不应报超时。
4. **复位**：清除故障后 bit7 清零、双方向解锁、电机不自行恢复转动。
5. 通过 0x2740 读取确认 bit7 置位/清除；结合 RTT 日志观察起算与截止时刻。
