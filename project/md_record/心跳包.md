# 心跳包功能说明

## 一、设计背景

Modbus RTU 协议中，MCU 作为从机，无法主动发起通信。主机需要定期轮询各从机以确认其在线状态。心跳包为此提供了一条专用寄存器，主机发一条读指令，从机回复自己的设备地址即可完成一次"存活确认"。

---

## 二、寄存器

| 地址 | 宏 | 读写 | 说明 |
|------|-----|------|------|
| **0x271F** | `REG_HEARTBEAT` | R | 心跳包，读回值 = 设备地址 (0x2710 的值) |

---

## 三、交互方式

### 定向查询（地址 1~247）

主机指定从机地址，仅该从机回复：

```
主机发送:  01 03 27 1F 00 01 crc_l crc_h
           ↑                    目标地址 = 0x01（1号从机）

从机回复:  01 03 02 00 01 crc_l crc_h
           ↑              数据 = 0x0001（node_id = 1）
           回复帧地址 = 0x01
```

### 广播查询（地址 0x00）

主机广播心跳包，总线上**所有从机同时回复**：

```
主机发送:  00 03 27 1F 00 01 crc_l crc_h
           ↑                    广播地址 = 0x00

从机A:    01 03 02 00 01 crc    （node_id=1 回复 0x0001）
从机B:    02 03 02 00 02 crc    （node_id=2 回复 0x0002）
   ...
```

> **警告**：广播模式下多从机同时回复，RS-485 总线电平冲突，主机可能收到乱码。仅适用于设备数量少、可容忍冲突的场景，或用于快速验证总线上是否有设备在线。

### 回复中两层蕴含 node_id

| 层 | 位置 | 含义 |
|-----|------|------|
| Modbus 帧头 | `buf[0]` | 回复帧的地址字节 = 从机自己的 node_id |
| 数据体 | `buf[3], buf[4]` | 寄存器值 = 从机自己的 node_id |

两者应一致。不一致说明 0x2710 配置异常。

## 四、固件实现

### 涉及文件

| 文件 | 改动 |
|------|------|
| `Utils/App_Params.h` | 新增 `#define REG_HEARTBEAT (0x271FU)`；从保留地址列表中移除 0x271F |
| `Utils/App_Params.c` | `Param_ReadByReg()` 新增 `case REG_HEARTBEAT: *pValue = g_AppParam.node_id;` |
| `App/App_Modbus.c` | `IsValidRegister()` 加白名单；`Modbus_ProcessFrame()` 地址匹配增加广播心跳逻辑 |

### 核心逻辑：Modbus_ProcessFrame() 地址匹配

```c
// 标准匹配：地址匹配 node_id → 放行
// 广播心跳：地址 == 0x00 && 功能码 == 0x03 && 起始寄存器 == 0x271F && 数量 == 1 → 放行
// 其他：丢弃

bool bIsBroadcastHeartbeat = false;
if (addr == 0x00U && func == MODBUS_FUNC_READ_HOLDING && dataLen >= 4U)
{
    uint16_t u16StartReg = ((uint16_t)buf[2] << 8U) | buf[3];
    uint16_t u16RegCount  = ((uint16_t)buf[4] << 8U) | buf[5];
    if (u16StartReg == REG_HEARTBEAT && u16RegCount == 1U)
    {
        bIsBroadcastHeartbeat = true;
    }
}

if (addr != g_AppParam.node_id && !bIsBroadcastHeartbeat)
{
    return;  // 地址不匹配且非广播心跳 → 丢弃
}
```

### 为什么仅 0x271F 支持广播

广播地址 `0x00` 仅对 `REG_HEARTBEAT` 的读操作开放。其他任何寄存器（包括写操作）不会响应广播地址，避免：
- 广播写 0x2710 导致全总线设备地址被批量修改
- 广播写 0x2720 导致所有电机同时动作

### 读路径

```
Modbus 0x03 请求 (addr=0x00 或 node_id)
  → Modbus_ProcessFrame()
    → 地址匹配放行
    → Modbus_HandleReadHolding()
      → Param_ReadByReg(0x271F, &value)
        → *pValue = g_AppParam.node_id   // 返回设备地址
```

心跳包是纯只读寄存器，不涉及 Flash 写入，不产生副作用。

## 五、modbus_tool 使用方法

```
主菜单:
  7. 心跳包

输入设备地址：
  - 输入 0 → 广播心跳包（所有从机回复）
  - 输入 1~247 → 查询指定从机
```

工具会显示发送指令和预期回令格式。

---

## 六、与标准 Modbus 广播的区别

| 维度 | Modbus 标准广播 (addr=0) | 本实现的心跳广播 |
|------|------------------------|----------------|
| 从机回复 | 不回复 | 回复 |
| 适用范围 | 所有功能码 | 仅 0x03 读 0x271F |
| 碰撞风险 | 无 | 有（多从机同发） |
| 用途 | 批量写（如急停全部） | 全呼存活确认 |
