# 关窗基准点功能说明

## 一、设计背景

现有实时角度（0x2731）依赖关窗过流校准，校准前角度无效，且掉电丢失位置。关窗基准点功能在此基础上新增：

- **独立于校准**：无论是否完成关窗过流校准，绝对角度都能正常追踪
- **掉电不丢基准点**：基准点通过 Flash 持久化，上电自动恢复
- **基准点可配置**：基准点角度值由 0x271C（关窗极限角度）定义，不硬编码为 0
- **欠压自动保存**：检测到欠压时自动将当前位置保存到 Flash
- **转动到目标角度**：支持 0x10 一条指令转动到任意角度

## 二、数据模型

### 核心公式

```
绝对角度偏移 = RAM实时偏移 = 相对关窗基准点的角度差 (单位 0.1°)

每 1ms 更新一次:
  delta = g_s32HallPulseAccum(当前) - s_last_accum(上次)
  s_abs_offset_x10 += delta × 3600 / (极对数 × 霍尔数 × 2 × 减速比)
```

### 关键变量

| 变量 | 存储位置 | 说明 |
|------|---------|------|
| `s_abs_offset_x10` | RAM | 实时偏移 (int32)，每 1ms 更新，掉电丢失 |
| `s_last_accum` | RAM | `g_s32HallPulseAccum` 的上次快照 |
| `s_target_x10` | RAM | 转动到目标角度的目标值 (int32, 0.1°) |
| `g_AbsAngle.abs_offset_x10` | Flash（扇区55） | 已保存的偏移值，掉电不丢 |
| `g_AbsAngle.goto_zero_thresh_x10` | Flash（扇区55） | 停止阈值 (0.1°), 回基准点和回目标共用 |
| `g_AppParam.close_limit_angle` | Flash（扇区56-62） | 关窗极限角度 (0x271C)，定义基准点的角度值 |

### 方向约定

```
开窗(FWD) → g_s32HallPulseAccum 增加 → 偏移增大 (正值方向)
关窗(REV) → g_s32HallPulseAccum 减少 → 偏移减小 (负值方向)

偏移 > 基准值(0x271C): 当前位置在基准点正方向（开窗方向）
偏移 < 基准值(0x271C): 当前位置在基准点负方向（关窗方向）
偏移 = 基准值(0x271C): 正好在关窗基准点
```

## 三、程序架构

### 文件结构

|------|------|
| `Utils/App_RunAngle.h` | 接口声明、结构体定义、宏 |

| `App/App_FaultHandler.c` | 欠压检测时自动触发保存 (RunAngle_Cmd(SAVE)) |
| `Dev/dev_rturn.c` | 关窗过流校准时调用 RunAngle_OnCalibration() |

### 程序流程

```
上电启动:
  main()
    → Hardware_Init()
    → ...
    → ESystem_Init()
      → Param_Init(&g_AppParam)   // 加载常规参数（含 0x271C close_limit_angle）
      → ... 设备初始化 ...
      → RunAngle_Init()           // 从 Flash 扇区55加载 abs_offset_x10 → RAM
                                  // 快照 g_s32HallPulseAccum → s_last_accum

主循环 (每 1ms):
  while(1)
    → ESystem_MainLoop()
      → ProcessDeviceUpdates()    // MotorHall update → g_s32HallPulseAccum 更新
                                  // dev_rturn 可能触发 RunAngle_OnCalibration()
      → RunAngle_Update()         // delta → s_abs_offset_x10 更新
                                  // 回基准点/回目标完成检测
      → ...

关窗过流校准 (dev_rturn 触发):
  g_s32HallPulseAccum = 0
    → RunAngle_OnCalibration()
      → s_abs_offset_x10 = 0x271C的值（不是 0）
      → g_AbsAngle.abs_offset_x10 = 0x271C的值
      → Param_Save → Flash 扇区55

欠压保存 (EventBus 回调):
  dev_voltage 检测到欠压
    → EventBus_Publish(TOPIC_VOLTAGE_ALARM)
    → App_FaultHandler::FaultHandler_OnVoltageAlarm()
        → RealTime_SetFault(bit6)
        → RunAngle_Cmd(ABS_CMD_SAVE)  ← 自动保存到 Flash
```

### 存储架构

```
Flash 扇区 55 (独立于常规参数扇区 62-56):
  使用 param_manager 多实例引擎
  结构体 AbsAngleRecord_t (32字节/条)
  魔数: 0xAB5AAB5A / 0xBA5ABA5A (独立, 防串扰)
  顺序追加写入 + CRC32 校验 + 磨损均衡
```

## 四、Modbus 寄存器

| 寄存器 | 地址 | 读写 | 数据类型 | 说明 |
|--------|------|------|----------|------|
| RAM偏移_LO | 0x2721 | R | int32 低16位 | 实时绝对角度偏移 (0.1°) |
| RAM偏移_HI | 0x2722 | R | int32 高16位 | |
| Flash偏移_LO | 0x2723 | R | int32 低16位 | Flash 中已保存的偏移 (0.1°) |
| Flash偏移_HI | 0x2724 | R | int32 高16位 | |
| 关窗基准点指令 | 0x2725 | W | uint16 | 命令寄存器 (见下表) |
| 停止阈值 | 0x2726 | R/W | uint16 | 回基准点和回目标共用停止阈值 (0.1°) |
| 目标角度_LO | 0x2727 | R/W | int32 低16位 | 回目标的目标角度 (0.1°) |
| 目标角度_HI | 0x2728 | R/W | int32 高16位 | 0x10连续写0x2727+0x2728即触发转动 |

### 0x2725 指令表

| 写入值 | 操作 | 说明 |
|--------|------|------|
| `00 00` | 设基准点并保存 | RAM = Flash = 0x271C的值, 写Flash扇区55 |
| `00 01` | 回到关窗基准点 | 转动到 0x271C 定义的角度, ⚠需解锁+停转 |
| `00 02` | 保存 RAM 偏移到 Flash | 固化当前偏移, 掉电后上电恢复 |
| `00 03` | 设当前位置为基准点 | 与 `00 00` 走同一分支, 行为完全一致 |

> **注意**：
> - `00 00` 和 `00 03` 走同一分支，行为完全一致
> - 基准点目标值由 `0x271C`（close_limit_angle）定义，不再是硬编码的 0
> - 例：0x271C = -20 → 设基准点时 RAM = Flash = -20 (即 -2.0°)

### 回基准点/回目标的安全门禁

回基准点（0x2725=0x0001）和回目标（0x10写0x2727+0x2728）共用两道门禁：

1. **RS485 控制锁** (`Param_IsCtrlUnlocked`)：必须先发 0x2720=0x0001 解锁
2. **电机停转检查** (`Param_IsMotorStopped`)：转动中拒绝执行

**回目标的门禁检查时机**（0x10 写 0x2727+0x2728）：

与回基准点不同，回目标的门禁检查在 **写入寄存器值之前** 执行。如果未解锁或电机在转，Modbus 返回异常码 04（SLAVE DEVICE FAILURE），且 `s_target_x10` 不会被覆盖。这保证正在执行的转动不会被意外干扰。

| 指令 | 门禁位置 | 不通过时 |
|------|---------|---------|
| 0x2725=0x0001（回基准点） | `RunAngle_GotoZero()` 内部 | 静默拒绝 |
| 0x10 写 0x2727+0x2728（回目标） | `Modbus_HandleWriteMulti` 写循环之前 | 返回异常 04 |

### 0x2726 停止阈值

| 操作 | 指令 | 说明 |
|------|------|------|
| 读 | `01 03 27 26 00 01` | 返回 uint16 (0.1°) |
| 写 | `01 06 27 26 00 0A` | 设 1.0° (值=10), 限幅 0~200, 写Flash, 热重载 |

### 0x2727/0x2728 目标角度

**写**（0x10 一条指令，写完即触发转动）：

```
01 10 27 27 00 02 04 [LO_H] [LO_L] [HI_H] [HI_L] CRC CRC
```

**读**（0x03 读 2 个寄存器）：

```
01 03 27 27 00 02  → 返回 4 字节 int32
```

目标角度为 int32 (0.1°)，范围 ±214748364.7°。写 0x2727+0x2728 后自动触发 `RunAngle_GotoTarget()`，同样经过解锁+停转门禁。

### Modbus 读写调度逻辑

**读路径（功能码 0x03）** — `App_Modbus.c` → `Param_ReadByReg()`

```
Modbus 0x03 请求
  → Modbus_HandleReadHolding()
    → Param_ReadByReg(regAddr, &value)
        ├─ 0x2721/0x2722 → RunAngle_GetOffset_x10()     // RAM 实时偏移 int32
        ├─ 0x2723/0x2724 → RunAngle_GetFlashOffset_x10() // Flash 已保存偏移 int32
        ├─ 0x2726        → g_AbsAngle.goto_zero_thresh_x10
        └─ 0x2727/0x2728 → RunAngle_GetTarget_x10()      // 目标角度 int32
```

**写路径**：

```
0x06 写 0x2725/0x2726:
  → App_Modbus 直接拦截 → RunAngle_Cmd() / RunAngle_SetThreshold()
  → 不走 Param_WriteByReg()

0x06 写 0x2727/0x2728:
  → Param_WriteByReg() → RunAngle_SetTarget_x10()（只存值，不触发）

0x10 写 0x2727+0x2728:
  → Modbus_HandleWriteMulti()
    ├─ ① 验证寄存器地址有效性
    ├─ ② ★ 前置门禁检查（在写寄存器之前）
    │     Gate 1: Param_IsCtrlUnlocked()? → false → 异常04, return
    │     Gate 2: Param_IsMotorStopped()? → false → 异常04, return
    ├─ ③ 写 0x2727 → RunAngle_SetTarget_x10(LO)
    ├─ ④ 写 0x2728 → RunAngle_SetTarget_x10(HI)
    └─ ⑤ 检测起始地址=0x2727 → RunAngle_GotoTarget()
```

## 五、操作指南

### 首次使用 (安装后)

```
1. 电机转到想要的"关窗基准点"位置（通常为关窗到底的机械极限位置）
2. 发: 01 06 27 25 00 00    → 设基准点并保存
   此时 0x2721/0x2722 读回 0x271C 的值（如 -20 即 -2.0°）
   此值由 0x271C (close_limit_angle) 决定
```

### 正常运行中读取角度

```
读 RAM 实时偏移:
  发: 01 03 27 21 00 02
  回: 01 03 04 XX XX XX XX crc_l crc_h
  解析: 4字节拼为 int32, ÷10 = 度数

读 Flash 已保存偏移:
  发: 01 03 27 23 00 02
  解析同上
```

### 回关窗基准点

```
1. 发: 01 06 27 20 00 01    → 控制开启（解锁）
2. 确认电机停转（读 0x2720，bit4=0 且 bit5=0）
3. 发: 01 06 27 25 00 01    → 电机转动到基准点
4. 到达后自动 ESTOP
5. 发: 01 06 27 20 00 02    → 控制关闭（上锁）
```

### 转动到目标角度

```
1. 发: 01 06 27 20 00 01    → 控制开启（解锁）
2. 确认电机停转
3. 发: 01 10 27 27 00 02 04 xx xx xx xx crc crc  → 设目标 + 转动
   例: 转 88.0° → 01 10 27 27 00 02 04 03 70 00 00 0E 3F
4. 到达后自动 ESTOP
5. 发: 01 06 27 20 00 02    → 控制关闭（上锁）
```

### 保存到 Flash

**手动保存:**

```
发: 01 06 27 25 00 02    → 保存 RAM 到 Flash
下次上电后自动恢复
```

**自动保存 (欠压触发):**

当系统检测到欠压时，`App_FaultHandler` 自动调用保存逻辑。用户无需手动操作。

### 停止阈值管理

```
读当前阈值: 01 03 27 26 00 01  → 返回 uint16 (0.1°)
设阈值:     01 06 27 26 xx xx  → 写入 0~200, 热重载立即生效
```

## 六、回基准点逻辑详解

### 6.1 前置检查

回基准点指令原本直接绕过 RS485 控制锁。已增加两道门禁，与 `REG_CTRL_CMD` 的 bit3~bit5 相同。

**调用路径**：

```
Modbus 写 0x2725=1 (00 01)
  → App_Modbus.c 拦截
    → RunAngle_Cmd(ABS_CMD_GOTO_ZERO)
      → RunAngle_GotoZero()
        ├─ 读 0x271C 获取基准点角度值
        ├─ Gate 1: Param_IsCtrlUnlocked()? → false → 拒绝
        ├─ Gate 2: Param_IsMotorStopped()? → false → 拒绝
        └─ 通过 → dist = 当前偏移 - 基准值
                → dist > +阈值 → REV
                → dist < -阈值 → FWD
                → |dist| ≤ 阈值 → 已在位置，不动
        → 设置 s_goto_zero_active = true

每 1ms (RunAngle_Update):
  dist = 当前偏移 - 基准值
  检查: |dist| ≤ 阈值 或 dist符号翻转 → ESTOP, 结束
```

**涉及文件**：

| 文件 | 改动 |
|------|------|
| `Utils/App_Params.h` | `Param_IsCtrlUnlocked()`, `Param_IsMotorStopped()` 声明 |
| `Utils/App_Params.c` | 两个 public 函数封装已有 static 变量/函数 |
| `Utils/App_RunAngle.c` | `RunAngle_GotoZero()` 入口门禁 + 目标值改用 0x271C |

### 6.2 回目标逻辑详解

与回基准点完全相同的门禁和停止判据，区别是目标值来自 0x2727/0x2728 而非 0x271C。

**⚠ 门禁检查时机**：门禁检查在写入 0x2727/0x2728 **之前**执行。如果未解锁或电机在转，整条 0x10 指令被拒绝并返回 Modbus 异常码 04，寄存器值不会被覆盖。这保证了正在进行的转动不会被意外干扰。

```
Modbus 0x10 写 0x2727+0x2728
  → 检测起始地址是否覆盖 0x2727
  → [前置检查] Param_IsCtrlUnlocked()? → false → 异常04 + 不写任何值
  → [前置检查] Param_IsMotorStopped()? → false → 异常04 + 不写任何值
  → 检查通过 → Param_WriteByReg 写 0x2727 → s_target_x10 LO
  → Param_WriteByReg 写 0x2728 → s_target_x10 HI
  → RunAngle_GotoTarget()
      → dist = 当前偏移 - s_target_x10
      → 方向判定 + 发布 FWD/REV → s_goto_target_active = true

每 1ms: |dist| ≤ 阈值 或 dist符号翻转 → ESTOP, 结束
```

### 6.3 方向判定

```
回基准点(目标=0x271C):
  dist = 当前偏移 - 基准值
  dist > +阈值 → REV
  dist < -阈值 → FWD

回目标(目标=0x2727/0x2728):
  dist = 当前偏移 - 目标值
  dist > +阈值 → REV
  dist < -阈值 → FWD
```

### 6.4 停止阈值

- 可通过 0x2726 寄存器配置，默认 1 (0.1°)
- 范围 0~200 (0° ~ 20.0°)
- 写入后立即生效 (热重载)，无需复位
- 回基准点和回目标共用同一阈值

### 6.5 回零中断

转动过程中可随时发 ESTOP (0x2720 bit2=1) 或过流保护中断转动。

## 八、与实时角度 (0x2731) 的区别

| 维度 | 实时角度 (0x2731) | 关窗基准点 (0x2721) |
|------|------------------|---------------------|
| 基准来源 | 关窗过流校准 | 0x271C 定义 + 过流自动同步 |
| 校准前有效 | 否 (返回0) | 是 |
| 掉电保留 | 否 | 是 (Flash + 欠压自动保存) |
| 更新频率 | 1ms (校准后) | 1ms (始终) |
| 数据类型 | int16 (0.1°) | int32 (0.1°) |
| 用途 | 限位、过流判断 | 位置记忆、回基准点、回目标 |

两者独立运行，互不影响。

## 九、关窗过流自动校准

### 9.1 设计动机

关窗到底的机械位置是最可靠的物理参考点。每次关窗过流时自动将基准点同步到该位置，消除因脉冲累积误差导致的漂移。

### 9.2 RunAngle_OnCalibration() 函数逻辑

```c
void RunAngle_OnCalibration(void)
{
    int32_t ref = (int32_t)g_AppParam.close_limit_angle;  // 读 0x271C

    __disable_irq();
    s_abs_offset_x10 = ref;                    // ① RAM = 基准值（不是 0！）
    s_last_accum = g_s32HallPulseAccum;        // ② 同步脉冲基线
    __enable_irq();

    g_AbsAngle.abs_offset_x10 = ref;           // ③ Flash = 基准值
    Param_Save(&s_Config, &s_Runtime);          // ④ 写入 Flash 扇区55

    MAIN_D("[ABSA] Calibration: RAM=%ld, Flash=%ld (0x271C=%ld)\r\n",
           (long)ref, (long)ref, (long)g_AppParam.close_limit_angle);
}
```

与旧版本的关键区别：旧版本硬编码为 0，新版本读取 0x271C 的值。

### 9.3 操作流程示例

```
通电 → 0x271C = -20 (-2.0°)
  │
  └─ 关窗到底 → 电机堵转 → 过流检测 → dev_rturn 校准
        │
        └─ RunAngle_OnCalibration()
              ├─ RAM → -20
              └─ Flash → -20
        │
        └─ 读 0x2721/0x2722: -20 (-2.0°) ✅
        │
  └─ 开窗到 88° → 读 0x2721/0x2722: 880 (88.0°) ✅
  │
  └─ 再次关窗到底 → 过流校准 → 绝对角度再次回到 -20 ✅
```

### 9.4 方案选择：每次关窗 vs 仅首次校准

| 维度 | 方案A：每次关窗都触发 | 方案B：仅首次校准（u8Calibrated 0→1） |
|------|----------------------|---------------------------------------|
| 触发条件 | 4个校准点全部触发 | 仅校准点1/3（首次校准时） |
| 每通电周期触发次数 | 多次 | 1次 |
| Flash 写入 | 每次关窗写一次 | 仅首次写一次 |
| 解决累积偏移 | ✅ 彻底解决 | ❌ 首次后的偏移仍会累积 |
| Flash 寿命影响 | 每天50次关窗可用160年 | — |

**选择方案A**。Flash 扇区55单扇区可写入 292万次（292条/扇区 × 10,000次擦除），关窗校准是低频机械事件（~20-40ms Flash 写入不影响实时控制）。

### 9.5 dev_rturn.c 中的 4 个调用点

`dev_rturn` 校准将 `g_s32HallPulseAccum = 0` 的时机分两条路径、四种场景：

```
RTurn_UpdateAngle()（轮询路径，每~50ms）
  │
  ├─ 校准点1：主动检查过流 + 反转方向
  │    首次校准（u8Calibrated = 1）+ 之后每次关窗都触发
  │
  └─ 校准点2：锁释放后重新检查 + 反转方向 + 已校准
       仅重复校准（不改变 u8Calibrated）

RTurn_HandleOvercurrent()（EventBus 路径，过流事件驱动）
  │
  ├─ 校准点3：限位触发 + 未校准 + 反转方向
  │    首次校准（u8Calibrated = 1）
  │
  └─ 校准点4：限位触发 + 已校准 + 反转方向
       仅重复校准（不改变 u8Calibrated）
```

**每个校准点在代码中的位置**（均在 `g_s32HallPulseAccum = 0;` 之后调用 `RunAngle_OnCalibration()`）：

```c
// 校准点1：轮询路径，首次+重复校准
if (u8CheckDir == RTURN_DIR_REVERSE) {
    g_s32HallPulseAccum = 0;
    pstcDev->fCurrentAngle = pstcDev->stcConfig.fMinAngle;
    if (!pstcDev->u8Calibrated) { pstcDev->u8Calibrated = 1; }
    RunAngle_OnCalibration();
}

// 校准点2：轮询路径，锁释放重检，仅重复校准
if (u8DesiredRTurnDir == RTURN_DIR_REVERSE) {
    if (pstcDev->u8Calibrated) {
        g_s32HallPulseAccum = 0;
        pstcDev->fCurrentAngle = pstcDev->stcConfig.fMinAngle;
        RunAngle_OnCalibration();
    }
}

// 校准点3：EventBus 路径，首次校准
g_s32HallPulseAccum = 0;
pstcDev->fCurrentAngle = pstcDev->stcConfig.fMinAngle;
pstcDev->u8Calibrated = 1;
RunAngle_OnCalibration();

// 校准点4：EventBus 路径，重复校准
pstcDev->fCurrentAngle = pstcDev->stcConfig.fMinAngle;
g_s32HallPulseAccum = 0;
RunAngle_OnCalibration();
```

### 9.6 主循环中的执行顺序

```
ESystem_MainLoop() (每 1ms):
  │
  ├─ ProcessDeviceUpdates()
  │     │
  │     ├─ MotorHall update       → g_s32HallPulseAccum 增量更新
  │     ├─ dev_rturn update       → 可能触发校准，清零 g_s32HallPulseAccum
  │     │                              └─ RunAngle_OnCalibration()
  │     │                                    ├─ s_abs_offset_x10 = 0x271C值
  │     │                                    ├─ s_last_accum 同步
  │     │                                    └─ Param_Save → Flash
  │     └─ 其他设备 update
  │
  └─ RunAngle_Update()            → 读 accum，计算 delta
        delta = 新accum - s_last_accum = 0 ✅ 不产生错误偏移
```

关键：`ProcessDeviceUpdates()` 中 dev_rturn 先于 `RunAngle_Update()` 执行。`RunAngle_OnCalibration()` 在 dev_rturn 校准路径中同步了 `s_last_accum`，确保后续计算 delta 时基线一致。

### 9.7 与手动设基准点的关系

- 手动设基准点（0x2725=0x0000/0x0003）和关窗过流自动校准走相同的底层机制，都是从 0x271C 读取目标值
- 两者互不冲突：用户可随时手动设基准点覆盖自动值，下次关窗过流会再次自动同步
- 如果用户需要"基准点在某个特定位置而非关窗极限位置"，应修改 0x271C 的值，然后手动发 0x2725=0x0000 设基准点
- 若需禁用自动同步行为，删除 `dev_rturn.c` 中 4 处 `RunAngle_OnCalibration()` 调用即可
